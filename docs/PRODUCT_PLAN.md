# Whooper 产品优化与商业化计划

更新日期：2026 年 10 月 19 日。状态：产品提案。下文的动效、文化包、社区 Store 和付费能力均为待开发范围，验收目标为建议值。

Whooper 的方向是一个有训练文化的个人数据与创作平台：用户记录训练，做出有个性的分享页，与朋友互相催练，也能创作和复用社区模板。网站、插件与开发者 API 使用同一套授权数据能力。

优先验证的产品循环是：**训练记录 → 创作分享 → 好友回应与催练 → 返回训练 → 复用或共创模板**。产品价值同时来自真实记录、持续训练和用户表达。

## 产品结构

避免继续为每个功能增加独立页面。以三个核心工作区组织长期产品：

| 工作区 | 用户任务 | 内容边界 |
| --- | --- | --- |
| 训练空间 | 看今天、查训练、跟进目标 | 身体状态、七天趋势、训练记录和详情；催练与挑战作为内嵌模块 |
| 创作工作室 | 把训练做成作品 | 选择训练、模板和文化包，实时编辑预览，导出、创建分享，管理已分享页面 |
| 模板 Store | 发现与共创 | 浏览风格、交互预览、收藏、使用、Fork、上传与协作发布 |

开发者控制台从账号菜单进入，独立管理应用授权、API 用量和账单，不占普通用户的主导航。设置、连接和主题各保留一个稳定入口。

Store 上线时，将当前“总览”和“训练记录”收进同一个训练空间，以内部视图和详情抽屉切换，保持三个主入口。

未登录访问网站进入 landing page；登录后才能使用工作区、上传模板、创建分享、催练和参与共创。已经创建的分享链接可公开只读查看，交互操作提示登录后继续。Landing 可以展示明确标注的交互示例。

当前 UI 去重的交付范围：总览保留指标、周趋势和最近三次训练；完整列表与动作明细归训练记录；分享创建与管理合并；只保留一份实际训练预览和一个主题入口。后续 Store 接入这一结构，避免重新长出重复页面。

## 交互与动效

每个动效应说明状态、帮助操作或增强分享表达，并提供减少动态效果设置。

| 场景 | 具体交互 | 验收方式 |
| --- | --- | --- |
| 数据总览 | 指标在真实数据到达后递增；点击周图某天展开当天训练；鼠标与触摸可读具体值 | 数据缺失、同步中和已休息有不同状态；键盘也可操作 |
| 训练明细 | 动作帧可播放或暂停；组数逐行展开；支持原始单位与显示单位切换 | 未记录与零重量保持区别；不生成不存在的训练数据 |
| 主题 | 保留 github.io 的卡片式主题切换，加入可中断的过渡 | 页面与图表同时换色，偏好持久化 |
| 模板选择 | 指针停留或点击播放短预览；选中后，同一份训练在原位置变换布局 | 无重复完整预览；手机有明确的点击操作 |
| 创作编辑 | 修改标题、贴纸、配色、模块顺序时实时预览；提供撤销与重做 | 数据与样式分离，编辑失败不丢草稿 |
| 分享完成 | 创建状态、成功反馈、链接复制与导出进度 | 不显示假进度，失败可重试，重试不重复创建 |
| 催练 | 按钮按压、一次反馈动画、状态变化和回执 | 冷却和去重在服务端执行，快速连点不会叠加 |

建议技术组合：

- **shadcn/ui 与 Radix**：整理按钮、页签、弹层、下拉、抽屉、表单、提示和空状态，统一键盘与焦点行为。现有项目已经使用 Radix Accordion，可逐步接入。[Radix 官方介绍](https://www.radix-ui.com/primitives/docs/overview/introduction)
- **Motion for React**：负责布局切换、手势、进出场和共享元素动效；简单悬停继续用 CSS。[Motion 官方文档](https://motion.dev/docs/react)
- **Recharts 与 shadcn Chart**：负责可点击的趋势图、提示和筛选；只按需加载图表功能。[shadcn Chart](https://ui.shadcn.com/docs/components/base/chart)
- PNG、公开网页和未来动图导出使用同一份数据与模板协议。动态模板需声明静态回退画面。

首批组件与主流程一同替换，避免一次安装多个视觉体系。优先使用变换和透明度动画，移动端降低粒子与连续动画密度，离屏动画暂停。

## 催练和薄肌文化

催练要成为训练记录与分享之间的连接。用户可选择今日计划、休息日、是否接受催练及展示范围。朋友从分享页进入，登录后发起一次催练；训练完成后展示回应或完成印章。数据暂不可用时显示未知，计划休息时显示休息状态。

首版保留三类动作：催练、鼓励、完成回应。个人可关闭或屏蔽催练，配置冷却与每日上限。先提供站内反馈，通知渠道在用户明确订阅后接入。

催练和完成回应保存为独立互动记录，按分享者选择的范围显示，不修改原训练快照。历史分享发起催练时，读取作者当前本地日期、接收偏好和休息计划，不能用旧训练日期推断今天是否训练。

现有催练接口固定服务于 `eazylee` 公开档案。产品化时需迁移为归属登录用户的档案、时区、规则和计数，避免把现有单人逻辑直接推广到所有账号。

“练薄肌”作为可选目标与表达风格，围绕本周训练次数、完成组数、训练量和持续周数呈现进展。WHOOP 数据不能直接证明外形或体脂变化；需要的身体记录由用户自行选择填写。

文化包作为模板之上的独立选择：认真训练、薄肌日记、朋友嘴替，以及用户提出的 **Alan Shao × Justin Sun 社区梗系列**。首批设计原创文案、贴纸、印章和短动效，用户可选择克制或夸张的语气。人物相关引用与素材记录出处，发布审核核对使用权限；实际联名另行建立授权流程。

每个文化包都能用于训练页回应、催练反馈和分享卡，训练数据与记录单位始终保持真实。文化包可由社区投稿、改编和共创。

## 模板 Store 与用户共建

### 发现和使用

Store 提供官方、社区、精选、最新和收藏视图，以手写、动作图鉴、薄肌日记、数据、Meme 等标签筛选。模板卡展示真实预览、作者、版本、支持字段、交互类型、使用数与授权方式。

用户可在示例数据与自己的已授权训练之间切换预览，选择使用、收藏或 Fork。作者主页呈现作品、被使用次数和衍生作品关系；早期排序优先完成质量、兼容性和真实使用反馈。

### 上传和协作

首版上传采用平台模板包，包含清单、布局配置、主题变量、素材、署名及授权信息。模板作者可用模块编辑器创作，也可导入经过校验的包。

发布流程：**私人草稿 → 示例预览 → 提交审核 → 发布版本 → 使用和反馈 → Fork 或协作更新**。

支持共同编辑邀请、明确的编辑与发布权限、修改记录、作者署名、上游来源、举报和下架。审核失败给出可修复原因；作者可以更新草稿。已发布版本不可原地覆盖，更新产生新版本。

Fork 继承上游署名和素材许可，记录允许的改编、商用与导出方式；随附的 CC BY-SA 动作插画继续履行其署名与相同方式共享义务。

### 模板协议

V1 定义 `schemaVersion`、`snapshotVersion`、主题变量、布局、组件、动效预设、素材引用和静态导出回退。平台提供指标、动作、组数、趋势、文字、贴纸和催练状态等组件，交互由平台 JavaScript 驱动。

社区上传包首版使用声明式配置。自定义 JavaScript 作为后续开发者能力单独评估隔离执行、资源预算与审核机制，避免模板获得访问账号、凭证或任意网络的能力。作者编辑时使用示例数据，使用者的真实数据由服务端按授权绑定。

公开分享继续采用训练字段白名单；社区模块、贴纸和文化包不能自动加入恢复、睡眠、心率或会员身份。扩展公开字段须有独立的用户选择与预览。

现有模板由四个固定枚举和数据库约束实现。Store 上线前必须演进到 Template、TemplateVersion、Asset、Review 和 Attribution，并为现有四模板保留兼容渲染。

每个分享绑定具体模板版本、渲染器版本和素材版本；作者更新模板不改变旧分享。下架与撤销规则区分作品发现、继续使用和历史渲染。现有随机链接、到期与即时撤销语义继续保留。

### 共建激励

先做免费共创：官方精选、创作者署名、使用反馈、Fork 谱系、主题征集与挑战共创。先验证创作者愿意制作、用户愿意使用，再开放付费模板。首批模板沿用已迁入的原版手写单与动作演示，并补齐薄肌、催练、周报和文化包示例。

## 商业化与开发者平台

建议先验证个人订阅，再开放模板交易，最后扩大开发者服务。具体价格基于成本和种子用户付费反馈确定。

商业可行性确认与第一阶段并行开展。WHOOP 于 2026 年 10 月 6 日生效的 API 条款限制转售 API 访问、材料与数据，并为 WHOOP 平台未提供的自有功能收费保留空间。商业路径先围绕创作、模板、导出和自建渲染能力设计；WHOOP 数据代理与转售型收费接口列为需取得明确许可后才能推进的范围。正式定价前核定产品边界、品牌与接口用途。[WHOOP API 条款第 3 节](https://developer.whoop.com/api-terms-of-use/)

| 产品层 | 价值与收费边界 |
| --- | --- |
| 免费个人版 | 基础训练空间、基础模板、有限分享和社区参与，保留用户对自身数据的管理能力 |
| Pro 个人版 | 高级创作、更多分享配额、高质量导出、动态呈现、长期对比与自定义品牌 |
| 创作者 Store | 先免费发布；之后增加付费模板、权益授权、收益账本、退款与分账 |
| 教练和团队 | 受邀成员授权、训练反馈、品牌模板与团队协作；成员权限独立管理 |
| 开发者 API | 优先开放模板渲染、导出与用户自有创作管理；项目级配额、明确权限、用量与计费，WHOOP 数据类收费另行确认授权 |

开发者 API 建立稳定的 `/v1` 契约、版本策略、示例、错误码、分页和 SDK。首批计费操作围绕模板渲染、导出和创作管理。区分本人访问与第三方代用户访问；后者走用户 OAuth 授权。REST 与 MCP 共享权限定义、计量和撤销机制，计量不代表所有数据访问均可对外售卖。

API Key 按项目管理，仅保存哈希，可轮换、撤销并限制权限；提供限流、月度预算、配额告警、幂等与审计。先统一成功操作和重试的计量规则，再接账单。公开分享读取使用快照，避免为每次浏览触发 WHOOP 实时调用。

规模化前先申请 WHOOP 更高成员档位。官方当前规定 Sandbox 为 10 人，后续依次为 Build 100、Growth 1,000、Scale 5,000 和 Production；默认请求额度为每分钟 100 次、每天 10,000 次。按应用实际获批额度设计同步、缓存和售卖配额。[成员档位](https://developer.whoop.com/docs/developing/app-approval/)、[调用限额](https://developer.whoop.com/docs/developing/rate-limiting/)

Strength Trainer 当前依赖单独连接的私有接口，需要独立核定允许的访问方式、商业用途与稳定性范围。先将其作为可降级的增强能力，不据此承诺付费服务等级，并规划手动训练录入或导入路径。

## 实施顺序与验收

下列工期用于排优先级，假设沿用现有技术栈、单名主开发并有设计内容协作；平台审核、支付开户和素材授权等待时间另计。

| 阶段 | 范围 | 初步工期 | 发布条件 |
| --- | --- | --- | --- |
| 第一阶段 交互基础 | 完成 UI 去重、统一组件、动效规范、可交互周图和动作播放控制 | 3–5 个开发日 | 核心任务无重复页面，手机与键盘流程完成，加载和异常状态可理解 |
| 第二阶段 分享与文化 | 单一实时编辑预览、薄肌文化包、登录催练与完成回应、可靠导出 | 5–8 个开发日 | 数据就绪后首次分享目标 60 秒内；真实账号完整流程验收 |
| 第三阶段 共创 Store | 模板协议、版本兼容、上传、审核、收藏、Fork、协作者权限 | 8–12 个开发日 | 社区作者独立完成发布；旧分享不随模板更新变化；越权和恶意素材测试通过 |
| 第四阶段 收费验证 | Pro 试点、开发者应用与权限、配额、用量和账单沙盒 | 8–12 个开发日 | 权益、账单、取消、退款与重复请求计量正确，单位成本可观测 |
| 第五阶段 生态交易 | 创作者付费模板、分账和团队协作 | 按试点结果排期 | 免费共创活跃、购买需求和支持成本得到验证 |

每阶段先交付一条可体验的完整用户流程，再扩展更多样式与组件。首个交互版本优先做：点击周图看训练、动作播放控制、模板实时切换、催练反馈、分享成功与失败回执。

## 产品指标与发布标准

核心指标采用每周有效训练记录用户数；辅助观察连接成功率、首次分享完成率、次周回访、催练后回访、模板使用和 Fork、活跃创作者、付费转化及每活跃用户服务成本。

首批在现有成员额度内建立基线，获批后扩大验证。先观察行为漏斗，再确定留存与付费目标，避免把浏览量、按钮点击或催练次数当成产品成功。

发布检查覆盖真实登录与授权、桌面和手机、减少动态效果、数据缺失和单位、分享到期与撤销、旧模板兼容、创作者权限、上传校验、导出，以及账单幂等。现有测试与 CI 作为基础，后续补充跨端浏览器流程和真实账号验收。

当前建议优先投入前两阶段，同时设计模板协议。免费共创 Store 是下一条完整产品线；付费与交易建立在实际使用反馈、授权范围和可观测成本之上。
